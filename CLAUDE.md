# OnePlan — Риэлторы

Закрытая база риэлторов (one-plan.pro). Язык общения с пользователем — русский.

## Структура
- `web/` — приложение: Next.js 16 (App Router, `src/`), React 19, Tailwind v4, TypeScript, Supabase (`@supabase/ssr`), `@tabler/icons-react`, Leaflet.
- `One-Plan приложение/` — дизайн-прототип из Claude Design. Источник истины по виду и поведению:
  `OnePlan Риэлторы.dc.html` (+ `support.js`, `image-slot.js` — рантайм прототипа, в продакшн не переносить).
  Открыть: сервер `python3 .claude/serve.py` → http://localhost:8765/OnePlan%20Риэлторы.dc.html
- `docs/prototype-realtors-spec.md` — разобранная спецификация прототипа риэлторов (экраны, модели, токены);
  `docs/prototype-developer-spec.md` — кабинет застройщика (`OnePlan v2.dc.html` + ТЗ: шахматка, планировки, журнал, права);
  `docs/prototype-other-spec.md` — лендинг, старый «Кабинет», мобильное App, «Цвета», ТЗ-print.
- `docs/crm-spec.md` — ТЗ CRM v2 (11.10.2026, на основе документа пользователя/GPT): сущности, поля заявок 4 типов, роли и филиалы,
  KVKK, EİDS, порядок работ; §13 — стандарт интерфейса 2026, §14 — ПРАВИЛА РАСПОЛОЖЕНИЯ И ИМЕНОВАНИЯ (тулбар: справа вид →
  плотность → фильтры → синее главное действие; «Канбан», не «Доска»; всё из формы видно в карточке; создание из карточки
  подставляет клиента). Правки делать в нём, не в чате; каждый новый экран сверять с §14.
- `docs/gaps-realtors.md` — чек-лист расхождений «код vs прототип» по экранам (аудит 19.09.2026). Закрывать пункты, не удалять файл.

## Как работать
- Git (11.10.2026): репозиторий — корень проекта (CLAUDE.md, docs/, web/, страницы прототипа без медиа), ветка `main`,
  GitHub private `git@github.com:mexmat77/oneplan-app.git` (ключ `~/.ssh/oneplan_github`, Host github.com в `~/.ssh/config`).
  Старый репозиторий программиста пользователь архивирует отдельно — не использовать. Правило: после каждой выложенной на прод
  задачи — `git add -A && git commit && git push` (коммит по-русски, кратко что сделано). В git НИКОГДА: `web/.env.local`,
  `*.docx` (логины/пароли), медиа прототипа — всё в `.gitignore`, перед коммитом смотреть `git status`.
- Node через nvm: `export NVM_DIR="$HOME/.nvm"; . "$NVM_DIR/nvm.sh"` перед `npm`.
- Dev-сервер: `cd web && npm run dev` (порт 3000). Launch-конфиги в `.claude/launch.json` подключаются по URL.
- Проверка: `npx tsc --noEmit && npx eslint src && npm run test:unit` (Vitest, `web/tests/unit/*.test.ts` — чистая логика: курс и
  округления, фильтры, справочник географии, подборки; `vitest.config.ts` алиас `@/` и заглушка `server-only`). Деплой гоняет всё
  это сам и останавливается при ошибке. Тесты уже ловили реальный баг (фильтр цены считал по старому курсу 48).
- Рассинхрон версий (12.10.2026): `deploymentId` в next.config.ts из `NEXT_DEPLOYMENT_ID`, который deploy.sh ставит при сборке —
  вкладка со старой версией при переходе перезагружается сама, а не падает на «Failed to find Server Action» (у пользователя было
  «Не удалось сохранить» при создании клиента сразу после деплоя). В CRM ошибки экшенов показывать через `crmError(e, fallback,
  readonlyText)` из crmUi: readonly / «Приложение обновилось — обновите страницу» с кнопкой / общий текст.
- Staging (10.10.2026): `./scripts/deploy.sh staging` → https://ai.one-plan.pro — старый поддомен после переезда на one-plan.pro
  отдан под тестовую копию (в nginx http://ai → https://ai, НЕ на основной; браузер мог запомнить старый 301) (та же база Supabase, `/var/www/oneplan-staging`,
  pm2 «oneplan-staging», порт 3001, `.env` с `NEXT_PUBLIC_STAGE=staging` → красный баннер «тестовая версия»). Сначала проверять
  на staging, потом `./scripts/deploy.sh` на прод. Мониторинг: `/api/health` (приложение + база) публичный; на сервере cron
  `/usr/local/bin/oneplan-watchdog.sh` каждые 5 мин, два сбоя подряд → письмо mexmat77@gmail.com через Resend, восстановление → письмо;
  pm2-logrotate 20 МБ × 14. Резервные копии базы и git/GitHub — по решению пользователя позже (см. память).
- Стиль: воспроизводим прототип пиксель-в-пиксель. Все цвета/радиусы/тени — токены в `web/src/app/globals.css`
  (`--ink`, `--text`, `--muted`, `--blue`, `--line`, …), в Tailwind как `text-ink`, `bg-blue-tint`, `border-line`.
- Тексты только через i18n: `web/src/i18n/{ru,en,tr}.json`, хук `useT()` из `@/i18n/provider`. RU — полный словарь,
  EN/TR частичные с фоллбэком на RU. Не хардкодить строки в компонентах.
- Маршруты приложения в `web/src/app/(app)/…`: `/catalog`, `/obj/[id]`, `/newb`, `/mine`, `/add`, `/favs`, `/sels`,
  `/reqs`, `/rls` (админ), `/chat`, `/ntf`, `/profile`, `/billing`, `/api-access`. Публичные: `/login`, `/s/[slug]`, `/join/[code]`.
- Supabase: ключи в `web/.env.local` (см. `.env.local.example`). Без ключей приложение работает в UI-режиме
  (вход пропускает без проверки, proxy не редиректит). `DEV_AUTH_BYPASS=1` в `.env.local` отключает проверку
  сессии в `proxy.ts` только в development — для вёрстки без аккаунта; в продакшн не попадает.
- Тестовые данные: `web/src/lib/seed.ts` строит 176 объектов из `web/src/mock/*.json` (порт генератора прототипа);
  `REALTORS`, `GEO`. Пока экраны читают их напрямую (`getSeedListings()`), позже — из Supabase.
- Данные риэлтора в Supabase (10.10.2026, миграции 0001 + `0012_realtor_data.sql` + `0013_price_history_trigger.sql` + `0014_price_history_after.sql` —
  триггер истории цен security definer и AFTER insert/update (BEFORE писал в price_history до появления строки → FK), иначе insert

  избранное (`favorites`, listing_id text — бывают демо-id), подборки (`selections` + `selection_items`: comment/sort/reaction),
  сохранённые поиски (`saved_searches`, `new_n`), запросы базы (`requests`, `request_replies`). Сторы НЕ изменились для экранов:

  объявления в базу (`migrateLocal`, фото через `lib/photos.ts` со сжатием до 1600 px) и чистит localStorage; при ошибке записи
  объявление остаётся в браузере (`keepLocalCopy`, уже с URL загруженных фото) и уедет позже. Страница объекта решает 404 только
  после гидрации И первой загрузки из базы (`useListingsReady(meId)`, флаг `loaded` в `remote`) — иначе объявления из базы давали 404. Демо-каталог прототипа (seed) остаётся рядом с базой. Без входа
  (DEV_AUTH_BYPASS) всё по-прежнему в localStorage. Владельцы: `store/realtors.ts` (`useRealtor()` = демо `REALTORS` + `profiles`),
  свой id — `useMeId()`/`getMeId()` из `store/profile` ("me" в демо). Профиль вошедшего для SSR идёт через контекст `ProfileCtx`
