ONEPLAN — платформа управления объектами застройки

Справочник к интерактивному прототипу OnePlan v2.dc.html. Описывает назначение, экраны, роли, устройство шахматки и правила поведения. Версия документа 2.0 · 21.07.2026.

Документ сопровождает рабочий прототип и служит образцом для боевой реализации. Прототип показывает как должно выглядеть и работать; серверную часть (база данных, сохранение, ссылки, авторизация) разработчики реализуют на своём стеке, используя прототип как эталон интерфейса и поведения.

⚠ Главное для разработчиков

Прототип не сохраняет данные — все правки живут в памяти вкладки и сбрасываются при перезагрузке. Это ожидаемо. Файл нужно открывать через локальный сервер (Live Server / python -m http.server), а не двойным кликом (file://), иначе часть данных не загрузится. Задача боевой версии — добавить постоянное хранение и API.

1. Назначение и суть

ONEPLAN заменяет застройщикам хаос из десятков Google-дисков единой закрытой B2B-системой. Вся информация по объекту (фото, видео, локация, документы, планировки, цены и статусы) хранится в одном месте, а клиенты и партнёры видят актуальную публичную страницу по одной ссылке. Застройщик управляет остатками (что продано / в брони / свободно), и это мгновенно отражается у всех, кто открыл ссылку.

Аудитория: застройщики, агентства, риэлторы (закрытый обмен объектами) и — на публичной витрине — конечные покупатели. Ориентация на турецкий рынок (структура папок, İskan, TAPU, типы планировок вида «2+1»).

2. Роли и модель доступа

Роль Уровень Права
Супер-админПлатформаВладелец системы. Управляет всеми компаниями и их объектами, создаёт/скрывает компании, задаёт срок доступа компании, назначает сотрудников платформы.
АдминистраторКомпанияВнутри своей компании: создаёт пользователей, правит реквизиты компании (видны клиентам), управляет объектами.
РедакторКомпания(и)Наполняет объекты (планировки, фото, цены, статусы). Может иметь доступ к нескольким застройщикам (сотрудники поддержки платформы). Пользователи ему недоступны.
МенеджерКомпанияПродажи — просмотр объектов и свои данные. Редактирование недоступно.

Иерархия: платформа → компании (застройщики) → пользователи и объекты. Сотрудник платформы (флаг «Платформа») не виден застройщикам в их списке команды, хотя имеет доступ к их объектам. Доступ компании задаётся сроком (дата или «бессрочно»); по истечении — доступ ко всем объектам компании закрывается (задел под платную модель).

3. Карта экранов

  • Лендинг — публичная главная: презентация, для кого, форма заявки, «бесплатно на время пилота».
  • Авторизация / Регистрация — вход, заявка на регистрацию с фиксацией согласий (договор, KVKK).
  • Объекты — список объектов застройки (карточки / список), фильтры по стадии, İskan, продажам; скрытые объекты «в тумане».
  • Карточка объекта — редактор: разделы Основное · Фото и видео · Описание · Локация · Дневник стройки · Документы; вкладки Объект / Планировки / Экспорт-импорт / Журнал / Настройки.
  • Планировки — Шахматка · Список · Поэтажный план (+ редактор сетки, создание планировок, модалка квартиры).
  • Настройки объекта — публикация/видимость, нумерация этажей, цвета, валюта, особенности, изображения планировок по типам.
  • Компании и доступы / Пользователи — управление компаниями и командами.
  • Профайл — данные пользователя, реквизиты компании, смена пароля.
  • Публичная страница объекта — как видит клиент: обложка, статистика, галерея, выбор квартиры, дневник, документы, локация, LIVE и промо-видео.
  • Публичная страница застройщика — все проекты компании + контакты.

4. Модель данных: помещение (unit)

Каждая ячейка шахматки — это помещение (квартира / коммерция / вилла) со следующими полями:

Поле Значение
uidУникальный внутренний id (не меняется).
numНомер помещения (виден пользователю). Пересчитывается автоматически по расположению.
floorЭтаж (число; 0 = цоколь/Z, отрицательные = подземные B1/B2).
posПозиция в ряду этажа (1,2,3…) — определяет колонку.
wingКорпус / блок (A, B, T=коммерция…). Пусто = один корпус.
bandСторона: out (окна наружу) / ins (окна во двор) — для объектов с двумя рядами на этаже.
typeКомнатность (1+1, 2+1, 3+1…; 1* = коммерция).
areaПлощадь, м².
priceЦена (валюта объекта). Цена/м² считается автоматически.
statusfree · booked · process · sold · reserve.
tagСпецтип: duplex · tduplex · triplex · terrace · и служебные.
td / entryДля триплекса: смещение вниз (0/1/2) и этаж(и) входа.
feats / ftОсобенности (терраса, сад, вид на море…). Можно несколько.
vl / vtФлаг «вилла» и тип виллы (для комплексов вилл).
wШирина плитки в клетках (1–3). Квартира занимает колонки pos…pos+w−1.
lxУстаревшее (старые импорты). Используется только как tie-break при одноразовой нормализации позиций — см. §5.

5. Планировки: единый движок шахматки

Движок один для всех объектов — без исключений. Ряды = этажи (сверху вниз), колонки = позиции pos. Базовая клетка 132×92 px, зазор 7 px. Один и тот же код рисует просмотр, редактор и публичную страницу; любая новая механика автоматически работает везде.

  • Ширина плитки (растяжка): квартира может занимать 1–3 клетки (w). В редакторе тянется за правый край: плитка следует за курсором пиксель-в-пиксель, при отпускании «дощёлкивается» до целых клеток (натянул больше половины соседней — заполняет её целиком, меньше — возвращается; анимация ~150 мс). Максимум ограничен свободными соседними клетками своего ряда. После ресайза клик подавляется — карточка квартиры не открывается.
  • Два ряда на этаже (band): «окна наружу» / «окна во двор» — для проектов, где на этаже два ряда квартир (пример — Megapolis, ~40 квартир на этаже). Подпись стороны — в колонке номера этажа. Занятость, растяжка ширины и выравнивание считаются в пределах своего ряда.
  • Наследие: сетки из старых импортов с «широкими» координатами нормализуются один раз при загрузке (пересчёт pos в 1,2,3… с tie-break по lx). Отдельного «координатного» движка нет.

Нумерация этажей настраивается на объект (данные не меняются, только отображение): Схема TR (B2·B1·Z·1·2…), Международная (B2·B1·G·1·2…), Цифровая (−2·−1·0·1·2…).

Сегменты / чипы: Все · Квартиры · Коммерция · Виллы (для смешанных комплексов). Коммерция и виллы показываются отдельными блоками. Строка статистики (Всего / Свободно / Бронь / Оформление / Продано / Резерв) кликабельна — фильтрует.

6. Спецтипы: дуплекс, ters дуплекс, триплекс

Многоэтажные квартиры занимают несколько рядов шахматки одной вытянутой плиткой с разделительными линиями между этажами. Верхняя граница плитки выравнивается по верхней границе обычных соседних плиток.

Дуплекс (2 этажа, вход снизу)

Растёт вверх: вход на нижнем этаже, второй уровень над ним. Стандартный дуплекс на промежуточных и верхних этажах. Одна разделительная линия.

Ters дуплекс (2 этажа, вход сверху)

Растёт вниз: вход на верхнем этаже, спуск на нижний (часто с цоколя вниз на B1). При установке автоматически появляется нижний этаж (B1).

Триплекс (3 этажа)

Занимает 3 ряда, две разделительные линии. Стандартный: −1·0·1 со входом на этаже 0. Возможны нестандартные варианты — вход на любом из 3 этажей (или на нескольких сразу), с бейджем «Вход · этаж». Можно опустить триплекс на −1 или −2 уровня (B1 / B2), эти нижние этажи дорисовываются автоматически.

Многоэтажные на этажах с двумя рядами (band)

Дуплекс/триплекс растягивается к клетке своего ряда на этаже выше/ниже. Три случая: (A) клетка своего ряда свободна и промежуточный ряд свободен → цельная вытянутая плитка; (C) клетка своего ряда свободна, но промежуточный ряд занят → на верхнем этаже рисуется «близнец» ⧉ — пунктирная копия той же квартиры (не кликается, не редактируется, высота ряда фиксированная); (бейдж) клетка своего ряда занята другой квартирой → плитка остаётся одноэтажной с бейджем «Дуплекс · 2 эт.». Две квартиры не могут претендовать на одну клетку — занятость учитывает уже растянутые.

Особые случаи для реализации: кнопки выравнивания (влево / пирамида / вправо) не должны схлопывать многоэтажные квартиры в одноэтажные и не должны накладывать их друг на друга — колонки многоэтажных резервируются на всех накрытых этажах (на двухрядных — в пределах своего ряда). Кнопки выравнивания доступны у всех корпусов в режиме редактирования.

7. Редактор сетки и перемещение плиток

Перемещение работает только в режиме «Редактировать сетку». В обычном просмотре клик по плитке открывает карточку квартиры.

Создание планировок

  • Вставка из прайса — скопировать строки из Excel/Google Таблиц; колонки (№, этаж, тип, площадь, цена, статус) распознаются автоматически.
  • Генерация сетки — задать число этажей и квартир на этаже (можно разное по этажам); сначала строится пустая сетка, параметры каждой квартиры заполняются потом кликом.
  • Можно добавить к существующим (новый корпус/блок) или заменить всё. Корпуса именуются и переименовываются; иерархия (квартиры → коммерция → виллы) сохраняется.

Перемещение (drag & drop)

  • Плитку можно перетащить на пустую пунктирную ячейку (слот) — она встаёт туда.
  • Плитку можно бросить прямо на другую плитку — они меняются местами (принцип «пятнашек»).
  • Групповое перемещение: зажать мышь на пустом месте и растянуть рамку — выделятся все задетые плитки; перетаскивание любой из них двигает всю группу. Ctrl-клик — точечно добавить/убрать. На тач-экране — долгое нажатие.
  • При перемещении номера квартир пересчитываются автоматически (в т.ч. при переносе на другой этаж).

Правка структуры

  • Кнопки Влево / Пирамида / Вправо — быстрое выравнивание квартир на этажах (относятся к своему корпусу).
  • + Квартира / + Этаж — добавление в конкретный корпус; крестик на плитке — быстрое удаление.
  • Масштаб 100 / 75 / 50% — уменьшить плитки, чтобы вместить крупный проект на один экран (для чисто-вилловых объектов масштаб скрыт — неактуален).
  • Пустоты (арки, пропуски) задаются пустыми местами в ряду.

9. Типы планировок

Автоматический тип = комнатность + площадь (м²). Квартиры с одинаковыми параметрами группируются в один тип; изображение планировки привязывается к типу и показывается во всех квартирах этого типа. При изменении площади квартира автоматически переназначается/создаёт тип, «осиротевшие» типы вычищаются.

Если при одинаковых параметрах планировки всё же разные (иное «нутро» или зеркальные) — создаётся отдельный тип вручную (Tip A / Tip A-R) и выбирается в карточке квартиры. К типу можно прикрепить несколько изображений (план, план 2-го этажа дуплекса, 3D-вид); первое — главное.

10. Медиа, документы, публикация

  • Фото и видео — по категориям (Социальная часть, Паркинг, Бассейн, СПА, Детская, Интерьер, Экстерьер…), drag-and-drop загрузка, изменение порядка, клик — просмотр с листанием (стрелки клавиатуры).
  • Дневник стройки — датированные фото/видео-отчёты с площадки; редактирование/удаление записей.
  • LIVE-трансляция — отдельная ссылка (YouTube Live / веб-камера); показывается пульсирующей кнопкой LIVE, когда эфир идёт (в кабинете, на карточке застройщика и на публичной странице).
  • Промо-ролик — ссылка на YouTube/Vimeo; кнопка ▶ на обложке публичной страницы, открывает плеер.
  • Документы — загрузка файлов, доступных для скачивания по внешней ссылке. Статусы док-в: Yapı Ruhsatı, İskan (юридический статус, отдельно от стадии стройки), TAPU, DASK.
  • Публикация / видимость: закрытая сеть ONEPLAN (по умолчанию) или публичная витрина. Объект можно скрыть по любой причине (не только завершение); скрытые/завершённые показываются «в тумане» и по умолчанию свёрнуты. Скрытый объект автоматически убирается с публичной страницы застройщика.

11. Прочее

  • Мультиязычность — RU / EN / TR на всех экранах. Описание объекта можно перевести ИИ и поправить вручную.
  • Готовность (%) — задаётся автоматически по стадии строительства, корректируется вручную. Стадии: Проект · Подготовка участка · Фундамент · Каркас · Фасад · Внутренние работы · Благоустройство · Завершено. İskan — отдельный статус (может быть получен до завершения благоустройства).
  • Экспорт / импорт — выгрузка шахматки и списка в Excel; импорт обновляет цену/статус/площадь по ID, не ломая структуру сетки. Рекомендация: сначала экспортировать, поправить в файле, импортировать обратно.
  • PDF — печать шахматки, списка и поэтажного плана (по текущим фильтрам).
  • Журнал изменений — кто и когда менял цены и статусы квартир (с постраничным выводом).

12. Командный чат

Внутренний чат сотрудников (кабинет + мобильное приложение, единая логика).

Статусы сообщений

  • ✓ отправлено (принято сервером) → ✓✓ серые доставлено на устройство → ✓✓ голубые прочитано. Только на своих сообщениях, в углу пузыря рядом со временем.
  • У каждого сообщения — время (HH:MM) в углу пузыря; дата — разделитель-таблетка по центру между днями («Сегодня · 21 июля», «Вчера», далее дата). В списке чатов у последнего сообщения — время или «вчера»/дата.

AI-перевод: каждый пишет и читает на своём языке

  • У сообщения хранится язык оригинала (автоопределение при отправке). Если он ≠ языку чтения получателя — показывается перевод с подписью «🌐 AI · TR → RU».
  • API: LLM-провайдер — планируются DeepSeek или OpenAI GPT (endpoint chat/completions; промпт: «переведи, сохрани смысл и тон, верни только перевод»). Провайдер — за абстракцией, заменяемый конфигом.
  • Кэш переводов по ключу (язык-цель + текст) — повторно не переводить. Пока перевод грузится — оригинал с индикатором «переводится…».
  • Тап по подписи перевода — показать оригинал этого сообщения (и обратно). Глобальный переключатель перевода на чат. Язык чтения по умолчанию = язык интерфейса, можно выбрать явно.

Транспорт и безопасность

  • Реальное время — WebSocket (или управляемый сервис типа Pusher/Ably). История в БД, TLS на транспорте; сквозное шифрование не требуется (корпоративный чат, история доступна с любого устройства).
  • Бейдж непрочитанных на иконке чата (шапка кабинета и таб-бар приложения) — тонкие цифры, кружок не перекрывает иконку.

13. Уведомления и журнал событий

  • Типы: продажа, бронь, смена статуса, изменение цены, новые фото/медиа, документы, новый объект. Генерируются автоматически по действиям пользователей.
  • Колокольчик в шапке: дропдаун с последними 7, счётчик непрочитанных, «Отметить прочитанными», ссылка «Все уведомления».
  • Страница «Все уведомления»: группировка по дням (Сегодня / Вчера / Ранее), фильтры-чипы по типам, порционная подгрузка — первые 20, кнопка «Показать ещё (20) · 20 / N»; при смене фильтра лимит сбрасывается. Клик помечает прочитанным и ведёт к объекту.
  • Видимость по ролям: пользователь видит события только своих компаний; сотрудник платформы (супер-админ, редактор поддержки) — по всем доступным, поэтому списки обязаны быть ограничены и пагинированы.
  • В мобильном приложении — push-уведомления (переключатель в профиле) + тот же список по дням.

14. Дашборд

  • Стартовый экран после входа. KPI-карточки (всего / свободно / продано / сумма по проданным), сегменты по статусам, график продаж по месяцам.
  • «По объектам»: первые 6 карточек, «Показать ещё (N)» / «Свернуть», счётчик «6 / N показано»; при >6 объектов — поиск по названию/локации/компании. Важно: у супер-админа и редактора поддержки объектов могут быть сотни.
  • Лента последних событий — 6 записей + ссылка на все уведомления.
  • Менеджер — только просмотр; блок команды — только у администратора.

15. Что реализовать в боевой версии

  1. Постоянное хранение (БД + API). Сейчас нет — все правки в памяти. Нужно: объекты, помещения, пользователи, компании, медиа, журнал.
  2. Аутентификация и роли по модели §2, ограничение доступа компании по сроку.
  3. Публичные ссылки на объект и застройщика с реальными данными и учётом видимости/публикации.
  4. Загрузка файлов (фото/видео/документы) в хранилище; отдача по ссылке для скачивания.
  5. Мультиязычные поля и ИИ-перевод описаний.
  6. Импорт/экспорт Excel с сопоставлением по ID.
  7. Чат — WebSocket, статусы доставки/прочтения, AI-перевод через DeepSeek/GPT с кэшем (§12).
  8. Уведомления — генерация по событиям, колокольчик, страница с группировкой и пагинацией, push в приложении (§13).
