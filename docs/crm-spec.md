две заявки у одного клиента, «комбинированный тип» не нужен.

## 1. Рабочее пространство, роли, филиалы [0017]

- Пространство CRM риэлтора = **агентство**, если у профиля есть `agency_id`; иначе личное пространство риэлтора-одиночки.
  Застройщик — компания, как сейчас.
- Роли внутри пространства (`crm_members.role`): `owner` (всё: настройки, все клиенты, экспорт, удаление), `manager`
  (руководитель филиала: все клиенты своего филиала, передача клиентов, отчёты филиала), `agent` (свои клиенты и те, что
  ему передали). Владелец по умолчанию — админ агентства (`profiles.role = admin` в агентстве) или сам одиночка; у застройщика —
  `dev_role = admin`. Роли и филиалы настраивает владелец в «Настройки → Команда».
- Филиалы `crm_branches`: название, город, руководитель; у сотрудника, клиента, заявки и сделки — `branch_id`. Фильтры
  «Филиал» в списках и воронке, счётчики на обзоре по филиалу. Одиночке раздел скрыт.
- Передача клиента другому агенту/филиалу — действие с записью в историю (`event kind = transfer`).
- RLS: `crm_ws_ok` расширяется на агентство (член агентства), `crm_ws_admin` — владелец/руководитель; руководитель видит
  клиентов своего филиала, агент — только своих (owner_id).
- Ключ шифрования остаётся на пространство (у агентства — один на всех сотрудников).

## 3. Заявка [0017]

Общее для всех типов: тип (`buy` / `sell` / `rent_out` / `rent_in`), статус (`active` / `matching` / `showing` /
`negotiation` / `paused` / `closed`), ответственный, филиал, приоритет, срок (`asap` / `1m` / `3m` / `later`), комментарий,
закрытые поля (видны владельцу и ответственному).

### 3.1 Покупка (`buy`)
Цель (жизнь / инвестиция / гражданство / ВНЖ / перепродажа / под аренду), тип недвижимости (квартира / вилла / коммерция /
земля / отель), расположение — окно İl/İlçe/Mahalle (несколько районов и махалле, как в форме объекта), бюджет от/до +
валюта, оплата (наличные / ипотека / рассрочка / обмен / после продажи своего), первый взнос, допустимый ежемесячный платёж,
комнаты (несколько), площадь от (net/gross), этаж от/до, возраст здания, состояние (новое / готовое / под ремонт), мебель
(да / нет / не важно), обязательные параметры (паркинг, бассейн, охрана, лифт, газ, вид на море…), желательные параметры
отдельно, готовность к просмотрам (дни/время), кто принимает решение, нужен переводчик, иностранный покупатель.
**[нет]:** минимальная доходность, зона на карте полигоном (вместо неё — махалле), UTM в заявке (есть у клиента).

### 3.2 Продажа (`sell`)
Объект из базы (ссылка на `listings`, можно создать объявление из заявки), клиент = собственник / представитель /
доверенное лицо, собственников (число) и совладельцы (ссылки на клиентов), цена публикации, желаемая цена, **минимальная
цена (закрытое поле)**, комиссия (% или сумма), срочность, причина продажи, объект свободен / живёт собственник / есть
арендатор (дата окончания договора), доступ для показов (свободно / по согласованию / ключи в офисе), маркетинговые
разрешения (фото / видео / дрон / соцсети / порталы), тип договора (эксклюзив / открытый), **Yetkilendirme Sözleşmesi**
(номер, начало, окончание, файл), право представительства (собственник / vekaletname), ипотека / арест / şerh (статус +
комментарий), статус документов (Tapu, İskan, DASK…), статус объекта (подготовка / опубликован / показы / оффер / задаток /
продан). EİDS — раздел 5.

### 3.3 Сдача (`rent_out`)
Поля собственника и объекта как в продаже, плюс: арендная плата + валюта, минимальная цена (закрытое поле), депозит
(месяцев или сумма), оплата (ежемесячно / 6 мес / год вперёд), aidat (сумма, включён или нет), минимальный срок, дата
освобождения, мебель и техника (есть / нет, ссылка на опись), допустимое использование (жильё / офис / коммерция), животные
(да / нет / обсуждается), требования к обеспечению (доход / поручитель / предоплата), коммерческая аренда (stopaj, счёт,
юрлицо), условия собственника, комиссия (кто платит и сколько), ключи (где и условия показа).

### 3.4 Аренда (`rent_in`)
Расположение, максимальная аренда + валюта, максимальный aidat, тип объекта, комнаты и площадь, мебель (обязательно / не важно /
без), дата заселения, срок, число проживающих, животные (вид и число), работа/компания, подтверждение дохода (есть / будет),
поручитель, готовность к предоплате (месяцев), нужна регистрация по адресу, на физлицо или компанию, время для просмотров,
обязательные условия (паркинг, школа рядом, бассейн…).
**[нет]** по совету документа: национальность, религия и другие спорные критерии отбора — не храним.

### 3.5 Как хранится
`crm_requests`: `id, ws_kind, ws_id, client_id, kind, status, owner_id, branch_id, listing_id, priority, deadline, fields jsonb,
closed jsonb (зашифровано: минимальная цена и другие закрытые поля), created_at, updated_at`. Набор полей по типу — реестр в
`lib/crm/requestFields.ts` (ключ, тип, варианты, обязательность, «закрытое»), формы и карточки строятся по реестру.
Текущие «Что ищет» + бюджет клиента при миграции становятся заявкой `buy`.

## 4. Подбор и показы [позже]
По заявке: список объектов (из базы OnePlan, подборок `selections`, новостроек) со статусами «отправлен / просмотрен /
понравился / отклонён», причина отказа, встречная цена, дата показа (= событие `show`). Публичная подборка `/s/<slug>`
уже умеет реакции клиента — они будут попадать сюда.

## 5. Объект продавца: EİDS и документы [0017, поля; проверка — позже]
В заявке `sell`/`rent_out` отдельные поля (не объединять): Yetkilendirme Sözleşmesi (номер, даты, файл), статус EİDS
(ожидается / активен / истёк / отозван), Taşınmaz ID, собственник (имя/наименование), срок разрешения, дата последней
проверки, причина ошибки EİDS, ID объявлений по порталам (sahibinden, hepsiemlak, emlakjet…). Реквизит агентства —
Taşınmaz Ticareti Yetki Belgesi (номер) — в «Реквизиты» (есть поле). Напоминание об истечении — задача за 14 дней.

## 6. KVKK [0017]
В карточке клиента, отдельным блоком, две независимые вещи:
1. **Aydınlatma Metni** (информирование, обязательно всегда): дата, способ (устно / WhatsApp / e-mail / форма сайта /
   бумага), версия текста.
2. **Açık Rıza** (согласие, когда оно основание): отдельные галочки на звонки, SMS, WhatsApp, e-mail; дата согласия, дата
   отзыва; правовое основание (согласие / договор / законный интерес); источник данных; срок хранения и плановая дата
   удаления/обезличивания.
Текущая одна галочка «согласие» переносится в «Açık Rıza: все каналы» с датой. Чувствительные документы (T.C. Kimlik,
паспорт, Tapu, доверенности, банковские данные) появляются только в сделке, в закрытом разделе «Документы» (есть), не в
карточке клиента.

## 7. Минимум при создании лида
Обязательные: имя, телефон или e-mail, тип заявки, источник, ответственный, район, бюджет или цена объекта, следующее
действие и дата (создаётся задача), статус Aydınlatma Metni. Остальное — по кнопке «Заполнить подробно» после выбора типа.
«Срок принятия решения» — необязательный.

## 8. Настройки пространства (кто и что)
Владелец пространства (админ агентства, одиночка, админ застройщика): этапы воронки (имена, цвета, порядок — [есть]),
источники, причины отказа [0017], реквизиты, шаблоны документов, команда и филиалы [0017], доступ сотрудников.
Руководитель филиала: только свой филиал (сотрудники, отчёты). Агент: ничего не настраивает.

## 10. Референсы (подборка пользователя/GPT 12.10.2026, проверенные)
- Pipedrive: воронка и карточка (до 7 полей прямо на карточке воронки: цена, район, тип клиента, следующий контакт,
  ответственный, приоритет, срок), индикатор просроченных задач, быстрые фильтры — https://support.pipedrive.com/en/article/pipeline-view
- amoCRM: карточка — слева данные, справа вся переписка/звонки/задачи/история — https://www.amocrm.ru/support/leads/card_view
- HubSpot: таблицы, сохранённые представления, настройка колонок — https://knowledge.hubspot.com/records/create-records-on-the-updated-index-page
- Follow Up Boss: карточка клиента с коммуникациями, показами, сделками и файлами на одном экране.
- Propertybase: объект ↔ клиенты ↔ показы ↔ офферы, **Matching** (автоподбор объектов под требования покупателя) —
  https://help.propertybase.com/hc/en-us/articles/360000362232-How-to-Use-Matching
- Next Heights: галерея экранов (лиды, объекты, собственники, показы, WhatsApp, аналитика агентов/комиссий/источников) —
  https://nextheights.in/screenshots.html
- Bitrix24: права и автоматизация (брать идею, не интерфейс).
Итог: **Pipedrive (воронка, простота) + Follow Up Boss (карточка клиента) + Propertybase (объекты, карта, matching)**.

## 11. Удобство (правило пользователя 12.10.2026: «не в 5 кликов, а в 1»)
- Даты: пресеты «Сегодня / Завтра / Через 3 дня / Через неделю» + часы одним кликом (`DuePicker`), точная дата — полем.
- Статусы и приоритеты: чипы и `Select` прямо в строке/карточке, без открытия формы (этап сделки, статус заявки, приоритет).
- Формы: минимум при создании, остальное раскрывается («Дополнительно», «Заполнить подробно»); все контролы 36px.
- Дальше: периоды дат в отчётах (сегодня/неделя/месяц/квартал/свой), быстрые действия при наведении, клавиатура («/» поиск,
  «n» новый клиент, Esc), drag&drop в канбане (есть).

## 12. Что ещё нужно риэлтору и застройщику (оценка 12.10.2026, по референсам)
Риэлтор/агентство: Matching (подбор объектов под заявку и покупателей под объект — у нас есть база и подборки), календарь
показов, собственники как отдельный список (клиенты с ролью продавец/арендодатель + их объекты и сроки EİDS), WhatsApp
внутри CRM (история переписки в ленте), отчёты по источникам/агентам/комиссиям, напоминания об истечении договоров
(Yetkilendirme, аренда), импорт из Excel/amoCRM.
Застройщик: лид → визит → бронь → договор → оплаты (график платежей и просрочки), бронь из сделки меняет статус квартиры в
шахматке, «кто привёл» и комиссии партнёрам-риэлторам, отчёты по проектам/корпусам, рассылки по базе покупателей.

## 13. Стандарт интерфейса 2026 (исследование 12.10.2026, задача пользователя «самое передовое, до миллиметра»)
Источники: Attio (changelog «Record page redesign» 2026, help «views»), Linear (views = сохранённые фильтры, Cmd+K, «/»),
Notion, HubSpot, обзоры SaaS-таблиц 2026 (setproduct, saasui.design, Pencil&Paper), паттерны Cmd+K и undo-toast.
Что считается нормой сейчас и что из этого у нас (✓ сделано, → делаем, ○ позже):

**Списки и таблицы**
- ✓ Фильтры — пилюли условий + «+ Фильтр» (Attio/Linear), панель «Все фильтры» справа; активные условия всегда видны, «Сбросить».
- → Сохранённые виды: любой набор фильтров + сортировка сохраняется под именем («Горячие покупатели Lara»), виды личные,
  последний открытый вид и фильтры запоминаются (Linear/Attio: «views are saved filters»).
- → Правка прямо в строке: ответственный, приоритет, статус контакта меняются селектом в ячейке, без открытия карточки.
- ✓ Действия строки — при наведении (позвонить, быстрый просмотр, открыть), групповые — тулбар над выбранными строками.
- ✓ Плотность компакт/развёрнуто, счётчик результатов, сортировка по колонкам. ○ Выбор колонок и их порядок, закрепление первой колонки.
- ○ Виртуализация при > 500 строк, бесконечная прокрутка.

**Навигация и клавиатура**
- → Cmd+K / Ctrl+K — командная палитра: поиск клиентов, переходы по разделам, «создать клиента/сделку/задачу», настройки;
  стрелки/Enter/Esc, подсказки сочетаний. «/» — поиск (✓), «n» — новый клиент, «Esc» — закрыть.
- ✓ Вкладки открытых карточек как в браузере; ✓ возврат к разделу без перезагрузки (кэш).

**Карточка записи (Attio 2026)**
- ✓ Заголовок, ключевые данные и главные действия в одном месте слева-сверху; ✓ атрибуты слева; ✓ лента справа.

### Передача клиента и роли агентства (12.10.2026)
- Роли в CRM агентства: **Администратор агентства** (все клиенты, настройки, команда), **Руководитель филиала** (свой филиал),
  **Риэлтор** (свои клиенты и клиенты без ответственного). Первый открывший CRM становится администратором; дальше роли меняет
  администратор («Настройки → Команда») или админ платформы («Данные риэлтора»).
- Смена ответственного — одно действие с одинаковым поведением везде: Select в строке списка, Select «Ответственный» в карточке,
  кнопка «Передать», групповое действие в списке. Право: ответственный за клиента, администратор, руководитель филиала.
  С клиентом переходят открытые заявки, сделки и невыполненные задачи прежнего ответственного; получатель получает уведомление.
- Передача вне агентства (другому риэлтору платформы) переносит карточку с перешифровкой; объекты передаются только внутри агентства.
- Источник — свойство клиента. В формах заявки и сделки его нет; сделка наследует источник клиента для отчётов.
- Карточка записи (клиент, сделка): шапка без статусов; одна полоса этапов; три колонки — «О …», активность, связи. Статус у каждой сущности в одном месте.
- Объект в сделке/заявке — из базы (объявление риэлтора / квартира застройщика) или свободно (текст + ссылка): нельзя заставлять
  указывать подробно. Поиск по базе: № объявления, название, район; разделы «Мои», «Избранное». Застройщик: проект → корпус →
  свободные квартиры. Выигранная сделка предлагает снять объект с продажи; проданный объект выставляется снова новым номером.
- Сортировка списка по умолчанию — последняя активность (события ленты и задачи), не «изменён». Любая колонка сортируется кликом; «Следующее действие» — без задачи в конце.

## 14. Правила расположения и именования (12.10.2026, задача пользователя «где что как должно быть, чтобы было нативно»)
Одно и то же действие — всегда в одном месте, с одним именем, одним видом. Проверять каждый новый экран по этому списку.

**Тулбар раздела** (одна строка над содержимым):
- слева: заголовок со счётчиком (Клиенты · 4) или сводка (сумма · 2 сделки) и фильтр по ответственному;
- справа, в этом порядке: переключатель вида (`Segmented`: Список/Канбан, Список/Неделя) → плотность (Компакт/Развёрнуто,
  только в списке) → «Все фильтры» → главное действие синей кнопкой «+ Создать / + Новая сделка / + Задача».
- Главное действие всегда крайнее справа и синее; второстепенные — белые с рамкой; опасные — красный текст без заливки.

**Имена**: канбан называется «Канбан» везде (не «Доска»); список — «Список»; «Создать» — в шапке CRM и в тулбаре клиентов,
«Новая сделка / Новая заявка / Задача» — внутри карточки. Статус клиента — «статус», этап сделки — «этап», статус заявки —
«статус заявки».

**Строки и чипы**: под тулбаром — виды (Все / Мои / …) с числами, ниже — чипы этапов с числами, ниже — пилюли фильтров и
«+ Фильтр». Клик по чипу этапа фильтрует, повторный клик снимает.

**Карточка записи**: шапка — аватар, имя · номер, чипы (язык, приоритет, роли, теги), строка «телефон · источник ·
ответственный»; справа в шапке — статус, приоритет, этап открытой сделки, «Позвонить», «WhatsApp», «Редактировать».
Всё, что есть в форме, видно в карточке (нет скрытых полей). Контакты — чипами с действиями: телефон → звонок и WhatsApp,
Telegram → t.me, e-mail → письмо, у всех — копировать.

**Создание из контекста**: «Создать → Сделка/Задача» внутри карточки клиента подставляет этого клиента и открывает окно сразу.

**Меню и всплывашки**: всегда в фиксированном слое поверх страницы (не режутся прокруткой), прижимаются к краю экрана,
открываются вверх, если снизу нет места; Esc закрывает; клик вне — закрывает.

**Изменения**: мгновенно (оптимистично), подтверждение — только для необратимого, для обратимого — тост «Отменить».

**Быстрые действия делают ровно то, что написано** (12.10.2026): «+ Добавить контакт» открывает маленькое поле на месте
(тип · значение · подпись · Добавить), а не всю форму клиента; у контакта — крестик «убрать». То же для любых «+ добавить»
в карточках: заметка, задача, заявка, документ — минимальный ввод на месте, полная форма — отдельной кнопкой «Редактировать».

**Передача (12.10.2026)**: объект — «Передать объект» на странице объекта (функция базы, права владельца/руководителя агентства);
клиент — «Передать» в шапке карточки: внутри команды меняется ответственный, вне команды карточка переезжает с перешифровкой;
получатель видит уведомление. Роль в агентстве назначает админ платформы в «Данные риэлтора» или владелец в CRM → Команда.
