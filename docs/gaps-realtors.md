# Gaps: приложение «Риэлторы» vs прототип `OnePlan Риэлторы.dc.html`

Легенда: [!] отсутствует/сломано · [~] отличается · [i] мелочь. Сгенерировано агентами-аудиторами 19.09.2026.

**Статус 19.09.2026 (вечер): все пункты закрыты**, кроме принятых отклонений ниже. При новом аудите — дописывать новые секции сверху.

Принятые отклонения от прототипа (осознанно, не переделывать):
- Тайлы карт — OSM вместо CARTO Voyager (CARTO требует API-ключ).
- Оверлеи прототипа `objModal`/`clientView` — у нас отдельные маршруты `/obj/[id]` и `/s/<slug>`; «Назад»/«В кабинет» возвращают на прежний экран через `sessionStorage`.
- Демо-предзаполнение логина (`realtor@one-plan.pro / Realtor1@plan`) — только при `NEXT_PUBLIC_DEMO_LOGIN=1`.
- Демо-переключатель роли «Риэлтор/Админ» показывается только реальным админам (в прототипе — всем).
- Переключатель рабочих пространств админа (Риэлторы/Застройщики/Управление) — расширение платформы, в прототипе риэлторов его нет; ниже 1560px — только иконки.
- «Написать в чате» автору без диалога создаёт новый диалог (прототип падал на `d1`).
- Публикация удаляет только свой черновик `aDraftId` (прототип чистил все).
- Supabase-вход, ошибка входа, `/join` с паролем, публичный `/s/[slug]` со счётчиком просмотров — расширения.
- Профиль → «Найти мессенджеры»: имитация прототипа заменена (решение пользователя 19.09.2026) на самоподтверждение — тумблеры WhatsApp/Telegram/Viber включает сам риэлтор, рядом ссылка «Проверить» (`wa.me`, `t.me/+…`, `viber://chat?number=`). Автоматической проверки номера в мессенджерах не существует (нет официальных API). Для реальных аккаунтов каналы по умолчанию выключены; имя/телефон/агентство/почта профиля — из Supabase `profiles`.
- Кабинет застройщика → лайтбокс фото/планировок (`components/dev/board/Lightbox.tsx`, общий для шахматки, объекта и публичной страницы): горизонтальная лента, стрелки ← → по краям, клавиши ←/→ (решение пользователя 23.09.2026); в прототипе `OnePlan v2` вертикальная лента со стрелками ↑/↓ справа.
- Публичная страница объекта `/p/[slug]` → легенда шахматки (`Legend stickyTop`) закреплена сверху под шапкой и якорями (top 114px), в прототипе липла снизу (решение пользователя 23.09.2026); на узких экранах чипы скроллятся внутри легенды.
- Кабинет застройщика → валюта: цены хранятся в валюте объекта и показываются как введены (ТЗ прототипа п.9); в прототипе цены в € × зашитый курс (USD 1.09, TRY 35). Курс ЕЦБ живой (`/api/rates` → api.frankfurter.dev, кэш 1 ч, запасной снимок в `lib/rates.ts`), показывается в настройках объекта; при смене валюты предлагается пересчёт цен по курсу; сводные суммы дашборда приводятся к €. Старые данные мигрируются один раз по курсам прототипа (`pricesIn`). На плитках суммы ≥ 1 млн сокращаются («18,7 млн ₺», полная сумма в title).
- Кабинет застройщика и `/p/[slug]` → поэтажный план, наведение (`FloorPlanView.tsx`, решение пользователя 30.09.2026): квартира под курсором выделяется «прожектором» (белый ореол + тёмный контур 3px, остальные приглушаются, подпись инвертируется), подсказка стоит вплотную к контуру и чисто информационная (без кнопки, клик по квартире открывает карточку); в прототипе `fpCard` — карточка в углу плана с кнопкой «Открыть карточку» и выдуманной зачёркнутой ценой ×1.12 (убрана).
- Кабинет застройщика и `/p/[slug]` → лента статусов (`Legend`) закреплена сверху во всех схемах: шахматка, список (`ListView header`, шапка таблицы встаёт под ленту), поэтажный план (счётчики выбранного блока/этажа, клик по статусу приглушает остальные квартиры); в прототипе легенда снизу и только у шахматки/списка. Список в режиме «Редактировать» — правка цены и статуса прямо в строке + колонка с карандашом и подсказка (в прототипе режим визуально не отличался). С поэтажного плана карточка в кабинете открывается сразу в режиме редактирования.
- Кабинет застройщика → добавление объекта (решение пользователя 30.09.2026): по умолчанию `/dev/objects/new` открывает мастер «Объект из файлов» (`components/dev/wizard/ImportWizard.tsx`: прайс-лист в любом формате + планы этажей → шахматка, ИИ-разметка, вырезки и типы собираются сами, в конце экран «Требует внимания»). Ручной мастер прототипа (§1.21) сохранён: `/dev/objects/new?manual=1`, ссылка «Заполнить вручную». Блок «Требует внимания» (`ObjectIssues`) есть и на странице объекта — в прототипе его нет.
- Главная `/` — лендинг прототипа «OnePlan Главная» перенесён генератором 1:1. Отклонения: язык общий с приложением (cookie), а не свой `lang` в `oneplan-lp-prefs`; «Войти» ведёт на `/login`; иконки — `@tabler/icons-react` вместо webfont; модалка KVKK/политики закрывается и по Esc; заявка реально отправляется в таблицу `leads` (в прототипе бэкенда нет), при ошибке — тост вместо экрана «спасибо». Открыто из спеки §A.12: отдельные маршруты `/kvkk` и `/privacy`, ссылки на магазины приложений (`#`), OG-метаданные.

- «Приглашение в базу»: ссылка создаётся по кнопке («Создать ссылку») или уходит письмом по почте, а не фиксированный `RLT-8F2K`.
- Карточка агентства: поле «Скан лицензии» в Supabase-режиме скрыто (загрузка файла в Storage не реализована).
- «Добавить» риэлтора создаёт аккаунт и отправляет письмо-приглашение (в прототипе — только запись в список).
