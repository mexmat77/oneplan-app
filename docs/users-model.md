# Пользователи, организации и роли (12.10.2026)

Единая модель по образцу Slack / HubSpot / Linear: **пользователь** ∈ **организация** с **ролью в ней**; приглашения и заявки
ведут в организацию. Миграция `web/supabase/migrations/0022_org_members.sql`.

## Сущности

| Сущность | Где | Что хранит |
|---|---|---|
| Пользователь | `profiles` | тип (`role`: `realtor` / `developer` / `admin` = администратор платформы), статус (`active` / `paused` / `pending`), оплата (`paid_to`), «сотрудник платформы» (`platform_staff`) |
| Организация | `agencies`, `developers` | реквизиты; у застройщика ещё директор, активность, срок доступа |
| Участие | `org_members` | `org_kind` (`agency` / `developer`), `org_id`, `profile_id`, **`role`**, `branch_id` (филиал CRM) |
| Приглашение | `invites` | код `/join/<code>`, почта, имя, тип пользователя, организация, **`org_role`** |
| Заявка на доступ | `access_requests`, `leads` | самозапись с формы входа / лендинга — админ одобряет и привязывает к организации |

Роли в организации:

| Организация | Роль (ключ) | Подпись | Права |
|---|---|---|---|
| Агентство | `owner` | Администратор агентства | все клиенты CRM, настройки CRM, команда и приглашения, реквизиты |
| Агентство | `manager` | Руководитель филиала | клиенты своего филиала |
| Агентство | `agent` | Риэлтор | свои объекты и клиенты |
| Застройщик | `admin` | Администратор | реквизиты, команда и приглашения, все клиенты CRM |
| Застройщик | `editor` | Редактор | наполняет объекты (планировки, фото, цены) |
| Застройщик | `manager` | Менеджер продаж | смотрит объекты, ведёт своих клиентов |

`profiles.agency_id` / `developer_id` («основная организация») и `profiles.dev_role` остаются для совместимости и
**синхронизируются триггером** `org_members_sync` из участия. Риэлтор состоит в одном агентстве; сотрудник застройщика может
состоять в нескольких компаниях (одна роль на все — так заведено в админке).

## Где что делается

| Кто | Где | Что может |
|---|---|---|
| Администратор платформы | `/admin/users` | все пользователи: тип, организация, роль в ней, статус, оплата, пароль, повторное письмо, удаление; ссылка-приглашение с организацией и ролью |
| Администратор платформы | `/admin/companies` → карточка `/admin/companies/<kind>/<id>` | реквизиты организации, участники с ролями, исключение, приглашения, «добавить существующего» |
| Администратор платформы | `/admin/requests` | заявки: «Принять» открывает окно — тип, организация (из справочника или **создать по названию из заявки**), роль |
| Администратор агентства | `/team` («Моё агентство» в меню) и CRM → Настройки → Команда | тот же компонент команды: роли, филиалы, приглашения, исключение |
| Администратор застройщика | `/dev/users` | команда своей компании (тот же компонент) |
| Любой участник | те же страницы | видит состав, менять не может |

Один компонент `components/org/OrgTeam.tsx`, одни серверные действия `app/org/actions.ts` (право: админ платформы или
администратор организации; запись сервисным ключом после проверки). Экран прототипа `/rls` с аккаунтом ведёт в `/admin/users`.

## Сценарии

- **Создать агентство и людей**: Управление → Организации → «Добавить» → карточка → «Пригласить» (почта + роль → письмо
  со ссылкой; без почты — ссылка для WhatsApp) или «Добавить существующего» (почта уже зарегистрированного риэлтора).
- **Сделать риэлтора администратором агентства**: в карточке организации или в `/admin/users` → «Редактировать» → роль в
  агентстве; администратор агентства может сделать это сам в «Моё агентство».
- **Человек зарегистрировался сам** (заявка на доступ): Управление → Заявки → «Принять» → выбрать/создать организацию и роль.
- **Исключить из агентства**: карточка организации → корзина; риэлтор становится свободным агентом, объекты и клиенты остаются
  у него (клиенты в CRM агентства — у агентства).
- Первый, кто открыл CRM агентства без назначенного администратора, становится администратором (`crm_claim_member`);
  последнего администратора снять нельзя.
